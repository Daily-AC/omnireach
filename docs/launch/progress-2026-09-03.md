## 这次踩到的两个自动化坑

1. **`opencli twitter reply` 不能发多行文本**。带换行必失败，报
   `Could not verify reply text in the composer after typing.`；同样的文本走 `twitter post`
   却没事。在一条一次性推文上做过 ASCII / 中文 / 多行 / 长单行四组对照，只有多行那组失败。
   解法是把 thread 里每条改写成单段。（`post` 在 7 月还能发多行，所以这是回归或 X 改版。）
2. **`opencli twitter reply` 不返回新推文的 id/url**，只返回 `status: success`。
   靠「发完再列最近推文取最新」来接龙不可靠——`twitter tweets` 的列表更新有延迟，
   连着三条都接到了同一个父节点上，thread 分叉了。已删掉重发修好。可靠做法是
   发完把已知 id 集合比对一遍，取那个新出现的。

另外知乎的编辑器**不吃 markdown**：`**加粗**` 和 ``` 代码围栏都会原样显示成字符。
这次答案发出去后才发现，已发的答案里留着 8 个 `**` 和 4 个 ``` 。试过四种改法
（重新 answer / DOM 直接改文本 / execCommand 逐个删 / 真实点击提交），
知乎的富文本编辑器都不认外部改动，提交后回读还是原文。**下次给知乎的稿子从一开始就写纯文本。**
