我最近一直在补 AI Agent 的一个盲区：它会搜网页，但一碰到微信公众号、小红书、
抖音、B 站、Twitter 线程这些真实内容源，就经常只剩一个搜索摘要，或者直接开
Playwright 硬闯。

所以做了 OmniReach。它给 Agent 提供统一的搜索、正文抓取和媒体解析接口：普通网页

刚发布的 v0.18 又加了受限的抖音视频下载。这里的重点不是“能下”，而是让 Agent
下载时有边界：必须显式选择 Chrome profile，可以限制文件大小和质量，落盘后
返回字节数和 SHA-256；匿名验证失败、超限和缓存校验失败都会明确报错。

它不替代 Playwright。点击、表单、上传和视觉测试还是浏览器自动化的工作。OmniReach
只负责让 Agent 在只读研究和媒体处理上有一条更稳的路。

开源 MIT：https://github.com/Daily-AC/omnireach

## Zhihu / Juejin

### Title

我给 AI Agent 补了一条通往中文互联网的路，现在它还能受控下载抖音视频

### Body

现在的 Coding Agent 已经很会调用工具了，但“能调用 WebSearch”和“真的能读到网络
内容”并不是一回事。

微信公众号、小红书、抖音、B 站，以及 Twitter、Reddit 这类依赖登录态或动态页面的
来源，往往只剩搜索引擎摘要。另一种常见做法是直接启动 Playwright，但如果任务只是
搜索或读正文，启动整套浏览器自动化既重，也把读取和交互混在了一起。

我做了一个开源工具 OmniReach，想把这两件事分开：

1. 普通网页优先走 HTTP，直接返回干净 Markdown，不启动 Chrome。
2. Google、Reddit、Twitter、小红书、TikTok、抖音等来源需要浏览器状态时，通过只读
   Chrome bridge 复用用户已经登录的会话，临时后台 tab 用完即释放。
3. 所有来源尽量收敛到统一 JSON，让 Agent 不必为每个平台重新猜字段。
4. YouTube、B 站和直接媒体 URL 可以解析元数据与字幕，长转录落到本地 artifact，
   不把整段文本塞爆模型上下文。

这次发布的 v0.18.0-alpha 新增了抖音视频下载，但我不想把它做成一个“给 URL 就无条件
下载”的黑盒。调用者必须显式发起下载并选择浏览器 profile，还可以通过
`--max-size-mb` 和 `--quality` 先限定边界。成功后返回本地 MP4
路径、实际字节数和 SHA-256；缓存复用前也会重新校验哈希。

真实验证中，`small` 格式得到一个 6,197,443 字节的 MP4，CLI 与 MCP 两条路径返回了
相同的 SHA-256。匿名访问遇到验证墙、文件超限或者缓存损坏时，工具会失败并给出恢复
提示，不会拿一段验证页假装下载成功。

OmniReach 仍然不替代 Playwright。点击、表单、文件上传、截图和视觉断言继续交给浏览器
自动化；它做的是 Agent 的只读研究层，以及有明确边界的媒体 artifact 层。

安装后可以直接运行：

```bash
omnireach search --on wechat "Claude Code 技巧"

omnireach media download \
  --cookies-from-browser "chrome:Profile 1" \
  --quality small --max-size-mb 100 --json \
  "https://www.douyin.com/video/<id>"
```

```text
Author disclosure: I built OmniReach. It is MIT-licensed, free, and has no paid plan or referral links.

The problem is that “Claude Code has web search” and “the agent can read the sources I actually use” are different things. WeChat articles, Xiaohongshu, Douyin, Bilibili, Twitter threads, and other login-backed sources are still awkward. The common fallback is to launch Playwright even when the task is read-only.

OmniReach separates those paths:

- omnireach_search returns normalized results across supported sources.
- omnireach_fetch returns clean Markdown.
- omnireach_parse_media materializes metadata and transcripts without flooding model context.
- omnireach_download_media creates a bounded local Douyin MP4 artifact.

Ordinary page reads use HTTP and do not start Chrome. Google, Reddit, Twitter, Xiaohongshu, TikTok, and Douyin search can use a small read-only Chrome bridge when the existing login is required. Temporary background tabs are released after the call.

The new Douyin download path is deliberately explicit: the caller selects a Chrome profile and can set quality and maximum size. Successful output includes the local path, byte count, and SHA-256. Search/fetch/parse never trigger a download as a fallback, and cookies or signed CDN URLs are excluded from the result envelope.

This is not a Playwright replacement. Clicks, forms, uploads, screenshots, and visual assertions still belong in browser automation.

Repo and release:
https://github.com/Daily-AC/omnireach
https://github.com/Daily-AC/omnireach/releases/tag/v0.18.0-alpha

I would especially value real failure reports: verification walls misclassified as success, poor Markdown extraction, bridge profile conflicts, or media artifacts that fail hash/cache checks.
```
