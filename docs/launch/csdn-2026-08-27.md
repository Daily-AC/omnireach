# AI Agent 能联网，却搜不到微信公众号——我开源了一个 CLI 来补这条路

> 利益相关：本文介绍的 omnireach 是我自己写的开源项目，MIT 协议，没有付费版、没有推广链接。写这篇是想找真实的失败反馈。

## 一个别扭的现实

现在的编程 Agent 都"能联网"了。Claude Code、Cursor、各种 Agent 框架都挂着 WebSearch 工具。

但你让它去查点中文技术内容试试。

微信公众号——搜索引擎收录得七零八落，Agent 拿回来的常常只是一句摘要。小红书、抖音、B 站——要么需要登录态，要么是动态渲染页面，Agent 直接抓一个空壳。Twitter 线程、Reddit 讨论，同样卡在登录墙外面。

于是"能调用 WebSearch"和"真的能读到我平时看的那些内容"，成了两件不同的事。

常见的补救办法是上 Playwright。但如果任务只是"搜一下"和"把这篇读进来"，为此启动一整套浏览器自动化，既重，也把**读取**和**交互**这两件本该分开的事混在了一起。

我写了 omnireach 来把它们拆开。

## 60 秒跑通

要求 Python 3.10+。

```bash
pip install omnireach
```

装完直接搜微信公众号，**不需要 API key，不需要登录**：

```bash
omnireach search --on wechat "Claude Code 技巧" --limit 2 --json
```

真实返回（只保留关键字段，实际还含 `content` 正文摘要和 `raw` 原始载荷）：

```json
{
  "query": "Claude Code 技巧",
  "results": [
    {
      "source": "wechat",
      "adapter": "sogou",
      "title": "Claude Code创始人15条技巧刷屏,但他其实只在说一件事",
```

注意 `adapter` 字段是 `sogou`——这条路走的是搜狗的公众号索引，免费，不碰任何私有接口，所以装完就能用。

## 三件事，一套 JSON

工具只做三件事，返回结构统一，Agent 不用为每个平台重新猜字段。

### 1. search — 搜

```bash
omnireach search --on hackernews "MCP protocol" --limit 2 --json
```

```
Show HN: mcpc – Universal command-line client for Model Context Protocol
  https://github.com/apify/mcp-cli
The Data Commons Model Context Protocol (MCP) Server
  https://developers.googleblog.com/en/datacommonsmcp/
```

`--on` 支持逗号分隔多个源，一次跨平台搜：

```bash
omnireach search --on hackernews,wechat "AI agent" --limit 6 --json
```

这条会同时返回 HackerNews 和微信公众号的结果。注意 `--limit` 是**每个源**的上限而不是总数——上面这条实际拿回 12 条（每个源各 6 条）。

### 2. fetch — 读全文

```bash
omnireach fetch "https://github.com/Daily-AC/omnireach" --json
```

```json
{
  "url": "https://github.com/Daily-AC/omnireach",
  "backend": "http",
  "fetched_at": "2026-08-27T08:19:24.329429Z",
  "content_markdown": "# GitHub - Daily-AC/omnireach: Search & read the login-walled...",
  "errors": []
}
```

`backend: http` 是重点：**普通网页走 HTTP 直接提取，全程不启动 Chrome**。返回干净的 Markdown，可以直接塞给模型。

只有确实需要登录态的源，才会去复用你已经登录的浏览器会话，用完即释放临时标签页。

### 3. media — 解析视频，而不是把视频塞进上下文

```bash
omnireach media inspect "https://www.youtube.com/watch?v=jNQXAC9IVRw" --json
```

```json
{
  "ok": true,
  "source": "youtube",
  "media_type": "video",
  "mode": "inspect",
  "cache_hit": false,
  "metadata": { "title": "Me at the zoo", "...": "..." }
}
```

`inspect` 只看元数据和有哪些字幕轨，不下载。`parse` 会把元数据和转录落成本地 artifact 文件——长转录不会一股脑灌进模型上下文，这是刻意的设计。

## 源的分层：哪些开箱即用，哪些要浏览器

这套东西最容易让人踩坑的地方，是分不清"装完就能用"和"得先登录"。所以我把源明确分了层：

| 层级 | 源 | 说明 |
|---|---|---|
| **ready** | hackernews、youtube、github、rss、**wechat**、**bilibili** | 零配置，装完即用 |
| **heavy** | google、reddit、twitter、**xiaohongshu**、**tiktok**、**douyin** | 需要复用你已登录的 Chrome 会话 |
| **booster** | tavily、brave、perplexity、exa | 付费 API，可选增强，不配也不影响 |

随时可以自查当前环境什么能用：

```bash
omnireach doctor
```

```json
{
  "omnireach_version": "0.18.0-alpha",
  "python": "Python 3.11.15",
  "platform": "Darwin 25.5.0 (arm64)",
  "sources": [
    { "id": "wechat", "tier": "ready", "ok": true,
      "detail": "Sogou 免费搜索 (httpx) (EXA_API_KEY 可选启用增强)" },
    { "id": "youtube", "tier": "ready", "ok": true, "detail": "yt-dlp 在 PATH" },
    { "id": "douyin", "tier": "heavy", "ok": true, "detail": "OpenCLI fallback 可用" }
  ]
}
```

每个源不 OK 时会给 `fix_hint`，告诉你缺什么、怎么补，而不是丢一个含糊的报错。

## 接进 Claude Code / 任意 MCP 宿主

它自带 MCP server，四个工具：`omnireach_search`、`omnireach_fetch`、`omnireach_parse_media`、`omnireach_download_media`。

```json
{
  "mcpServers": {
    "omnireach": {
      "command": "omnireach",
      "args": ["mcp"]
    }
  }
}
```

配好之后，Agent 做只读研究就不必再去开浏览器自动化了。

## 关于抖音下载：边界写死在参数里

v0.18 加了受限的抖音视频下载。这里的重点不是"能下"，而是**不做成一个给 URL 就无条件落盘的黑盒**：

```bash
omnireach media download \
  --cookies-from-browser "chrome:Profile 1" \
  --quality small --max-size-mb 100 --json \
  "https://www.douyin.com/video/<id>"
```

几条硬约束：

- 必须**显式**发起下载并指定浏览器 profile，`search` / `fetch` / `parse` 永远不会"顺手"触发下载
- `--max-size-mb` 限制体积（默认 500，可设 1–5120），`--quality` 在兼容性/最高画质/最小体积之间选
- 成功返回本地路径、实际字节数和 **SHA-256**
- 命中缓存时会**重新校验哈希**再复用，坏缓存直接报错
- 结果里不含 cookies 和签名 CDN 链接
- 遇到验证墙、超限、缓存损坏，工具明确失败并给恢复提示，**不会拿一段验证页假装下载成功**

最后这条是我写这个工具时最在意的。Agent 拿到一个"成功"的返回却是垃圾内容，比直接失败糟糕得多。

## 它不替代 Playwright

说清楚边界：**点击、表单、上传、截图、视觉断言，继续交给浏览器自动化**。

omnireach 只负责两件事：Agent 的**只读研究层**，和有明确边界的**媒体 artifact 层**。这两件事今天被 Playwright 顺手兼了，但它们本不该那么重。
