### Post 3

Why exact: the call runs inside your logged-in page context, where Douyin's own
web JSON API needs no request signing. A DOM card only renders likes, so a
scraper has to zero-fill the rest.

`views` is still reported unknown — that endpoint always returns 0, and
guessing would be worse than admitting it.

### Post 4

v0.19 also closes a failure-reporting hole that mattered more than any feature.

A failed command used to answer `ok: false` with an empty `errors` list — which
reads exactly like "ran fine, found nothing". Every CLI and MCP failure path now
fills `errors`, and tracebacks go to stderr instead of corrupting the JSON on
stdout.

### Post 5

5 MCP tools over one normalized schema:

`search` / `author` / `fetch` / `parse_media` / `download_media`

WeChat search works with zero configuration and no API key. Not a Playwright
replacement — keep that for clicks and forms. This is for read-only research.

MIT, no LLM inside. https://github.com/Daily-AC/omnireach

## Zhihu / Juejin

### Title

让 AI Agent 搜到「这个人发过什么」——OmniReach v0.19 的一个小发现

### Body

先说一个我自己撞上的具体失败。

我让 agent 去抖音上找创作者「彭十六」的作品，它老老实实跑了搜索，返回三条视频，
按点赞排序——`大喵喵`、`大白show`、`抓马娱乐`。一条都不是她的。

这不是 bug，是维度错了。关键词搜索匹配的是**文案**，谁的视频文案里出现过这三个字、
谁的数据又好，谁就排在前面。你想问的是「这个人发过什么」，工具能回答的却是
「谁提到过这个词」。

所以 v0.19 加了 `omnireach author`：

```bash
omnireach author "彭十六" --order likes --limit 5
```

它先把名字解析成账号（彭十六elf，2819.5 万粉丝），然后翻完这个号的全部 355 条作品，
`complete: true`，实测 45 秒。第一条：

    把东方美学带到欧洲 #卢浮宫 #马面裙
    6,534,088 赞 / 127,865 评论 / 473,803 转发 / 252,269 收藏

这些数字是精确值，不是估算。原因值得说清楚：这个调用发生在**你自己已登录的页面上下文里**，
抖音自家的 web JSON 接口在那个上下文中不需要 `a_bogus` / `X-Bogus` 签名。而 DOM 卡片
只渲染点赞一个字段，靠爬卡片的路子只能把其余三项填 0——一个「0 转发」的视频和一个
「不知道多少转发」的视频，对 agent 来说是完全不同的两件事。

同样的诚实要求也用在反方向：播放量我们报「未知」。那个接口的 `play_count` 恒为 0，
猜一个数比承认不知道更糟。

### 比新功能更重要的那个洞

真正让我停下来的是另一件事。有人报 `omnireach media download <url> --json` 静默失败。
我以为是媒体层的问题，查下去发现根因在 CLI 最外层：任何参数错误都会被渲染成

```json
{"ok": false, "error": {"type": "usage_error", "...": "..."}}
```

——**没有 `errors` 字段**。而所有 agent 读失败的写法都是 `envelope.get("errors", [])`。
于是它拿到一个空列表，得出的结论是「跑完了，什么都没找到」。一个从来没到达后端的失败，
长得和一次成功的空结果一模一样。

v0.19 把 CLI 和 MCP 的每一条失败路径都补上了 `errors`；崩溃的 traceback 从 stdout 挪到
stderr（agent 正在 stdout 上解析 JSON，往那儿打印堆栈等于把它的输入弄脏）；MCP 各工具的
异常兜底以前返回 `{"error": "..."}`，而它们自己声明的 outputSchema 根本不接受这个形状，
现在返回真正的信封。

顺带一个只有实测才能得出的结论：抖音匿名 cookie 的抖动，冷启动 1/10 失败、被限流后
4/10，而 1 秒间隔和 5 秒间隔的失败率**一样**。所以加重试次数有用，加退避没用。定成
4 次尝试共享一个超时预算。

### 这是什么

OmniReach 是一个开源 CLI + MCP server，给 agent 补上登录墙后面的中文互联网：
微信公众号、小红书、抖音、B 站，加上 Twitter / Reddit / HackerNews / YouTube。
五个 MCP 工具走同一套 JSON 契约：`search` / `author` / `fetch` / `parse_media` /
`download_media`。

微信公众号搜索**零配置**，不需要任何 API key。

普通网页走 HTTP；确实需要登录态的源，才通过一个只读的 Chrome 扩展复用你现有的会话，
临时后台标签页用完即关。它不替代 Playwright——点击、表单、上传、截图请继续用
Playwright，OmniReach 只做只读检索和有界的媒体产物。

MIT，本体不含 LLM。https://github.com/Daily-AC/omnireach

装法是一句话：把下面这行给你的 agent，让它自己装。

```bash
curl -fsSL https://raw.githubusercontent.com/Daily-AC/omnireach/main/install.sh | sh
```
