# v0.14.0-alpha - Omnireach native Chrome bridge

Douyin search no longer requires the OpenCLI executable. Omnireach now ships its own small,
read-only MV3 extension and a dependency-free Python localhost bridge that reuse the current
Chrome profile's Douyin login.

## What Changed

- Added `omnireach bridge install`, `bridge path`, and `bridge status --json`.
- Added a bearer-authenticated, loopback-only, short-lived command server using Python's
  standard library.
- Added an Omnireach-owned Chrome extension with narrow localhost and Douyin permissions.
- Migrated `douyin.search` to native Chrome first, with OpenCLI as compatibility fallback.
- Added `OMNIREACH_BROWSER_TRANSPORT=auto|native|opencli` for deterministic diagnosis.
- Kept temporary search UI non-focused and minimized, and close it in a `finally` path.

The native extension accepts only `system.ping` and `douyin.search`. It does not request
cookie, debugger, or `<all_urls>` access, and no new Python runtime dependency was added.

## Setup

```bash
omnireach bridge install
omnireach bridge path
omnireach bridge status --json
```

Load the printed directory once from `chrome://extensions` with Developer mode enabled,
then sign in to `www.douyin.com` in that Chrome profile.

## Verification

- Authenticated bridge protocol tests use a real loopback HTTP server.
- Extension projection logic runs under Node against a response shape captured from a real
  Douyin result card.
- Transport tests prove native preference, unavailable-only fallback, forced-native OpenCLI
  bypass, and surfaced native contract failures.
- A forced-native logged-in Douyin E2E is required before release publication.

## Install Or Upgrade

```bash
uv tool install --force 'omnireach==0.14.0a0'
```
