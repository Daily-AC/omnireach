# v0.18.0-alpha - Bounded Douyin media downloads

OmniReach can now turn an explicitly requested Douyin URL into a bounded,
hash-verified local MP4 artifact for agents.

## Added

- `omnireach media download <douyin-url>` with stable JSON output.
- `omnireach_download_media` over MCP, alongside search, fetch, and media parsing.
- Explicit browser-cookie handoff through `--cookies-from-browser`; OmniReach never
  silently reads a logged-in browser profile.
- `--quality compatible|best|small` and `--max-size-mb` controls before bytes are
  accepted.
- SHA-256-addressed artifacts, byte-count verification, and hash-checked cache reuse.

## Failure and privacy boundaries

- Anonymous Douyin verification failures return `category=blocked`, a concrete
  browser-cookie recovery hint, no artifact, and a non-zero CLI exit code.
- Downloads that exceed the configured size limit fail without leaving a
  usable artifact.
- Browser profiles, cookies, signed CDN URLs, and expiring thumbnail signatures are
  excluded from envelopes and manifests.
- Media downloads remain explicit operations; search, fetch, inspect, and parse never
  trigger them as a fallback.

## Real upstream verification

The release was exercised against a real Douyin video with an explicitly selected
Chrome profile. The `small` format produced a 6,197,443-byte MP4; `ffprobe` reported
576x768 HEVC video plus AAC audio, and both CLI cache reuse and the stdio MCP tool
returned the same SHA-256 digest.

See [the complete verification record](../verification/douyin-download.md) for the
upstream format shape, anonymous failure, size-limit rejection, cache, privacy, and MCP
checks.
